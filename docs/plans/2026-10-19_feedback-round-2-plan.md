## PR-A：前台展示类（无数据库迁移）

### A1 价格显示两位小数
- `formatMoney`：整数英镑仍显示 `£6`，有便士时显示 `£6.30`（`minimumFractionDigits` 按是否整除 100 决定）。
- 后台价格输入框已用 `Math.round(x * 100)` 存便士，确认 `step="0.01"`，不再被浏览器校验拦住。
- 测试：`formatMoney(630)` → `£6.30`，`formatMoney(600)` → `£6`。

### A2 “已有搭子”标签
- 规则：已发布、未满、`bookedSpots > 0`（含标记已满以外的所有场） → 卡片显示“已有搭子 · N 人已报名”的高亮标签；空场保持原样。
- 位置：Courtside 首页列表、详情页名额区。新增翻译 key `partnerJoined`。
- 首页筛选加一个“已有搭子”选项（与单打/双打筛选并列），方便只看能马上组局的场。

### A3 首页本周场次地图
- 依赖：`leaflet@1.9.4`（OpenStreetMap 瓦片，页面带署名）。只在首页地图区域进入视口后动态 `import()`，不影响首屏。
- 坐标：前端用 postcodes.io 批量接口（免费、支持 CORS）把场地邮编转经纬度，结果按邮编缓存到 `localStorage`。没有邮编的场地不上图。
- 内容：显示未来 7 天内已发布的场次，按场地合并成一个标记；点开弹窗列出该场地本周的场次（日期、时间、剩余名额），点击跳转详情。
- 位置：首页场次列表上方，“本周场地地图”区块；手机端高度 260px。

### A4 找球友看板按邮编筛选
- 把 Area 下拉框换成 “Post Code” 输入框 + 距离下拉（1 / 2 / 5 / 10 英里，默认 5）。
- 支持完整邮编（`SE1 7PB`）和前半段（`SE1`）：分别调 postcodes.io 的 `/postcodes` 和 `/outcodes`。
- 每条需求的位置：已知场地用场地邮编，`find_nearby` 用需求邮编（公开 API 已返回 `postcode`）。按直线距离过滤并按远近排序，卡片显示“约 1.2 英里”。
- 邮编查不到时提示“找不到这个邮编”，不清空列表。

### A5 二维码
- 依赖：`qrcode@1.5.4`，在浏览器端生成。
- 后台新增“宣传二维码”卡片：首页链接的二维码，可下载 PNG（1024px，适合印刷）和 SVG。
- 后台场次列表每场加“二维码”按钮，生成该场详情页链接的二维码。

## PR-B：24 小时前自动退款（迁移 `0023_auto_refunds`）

### 规则
- “没有合适的球友搭配” = 场次开始前，所有有效报名的**参与人数合计 < 2**（只有一个人报名，没人跟他打）。一个预订里带了朋友（2 人以上）就不退。
- 管理员“标记已满”的场次不自动退款（说明线下已经有人）。
- 场次级开关暂不做：管理员可以用“标记已满”让某场不参与自动退款。
- 判定时把正在付款中的人也算进去，避免刚好有第二人在付款时误退。

### 时间
- Vercel Hobby 的 cron 只能每天跑。新 cron `/api/cron/auto-refunds` 每天伦敦时间 18:00 运行（UTC 17:00 和 18:00 各一条，按现有 reminders 的夏令时写法）。
- 每次处理“开始时间在 24–48 小时之后”的场次 → 保证至少提前 24 小时退款。代价：周六 10:00 的场在周四 18:00 判定，最后一天内不再等人。
- 窗口用常量 `AUTO_REFUND_LOOKAHEAD_HOURS = 24` 表示 cron 间隔，以后升级 Pro 改成每小时跑时只改这个值。

### 实现
- `bookings` 新增 `auto_refund_status`（`none` / `processing` / `refunded` / `failed`）和 `auto_refunded_at`。先用条件 UPDATE 认领（防止两条 cron 重复退款），再调 Stripe `POST /v1/refunds`（`payment_intent`，幂等键 `auto-refund-<bookingId>`）。
- 退款成功后预订状态改为 `refunded` 并释放名额；只有仍为 `confirmed` 时才释放，所以 webhook `charge.refunded` 先到也不会重复释放。免费预订直接取消，不调 Stripe。
- 一场的预订全部处理完后，场次改回草稿，避免再有单人报名。
- 用了优惠券的预订本轮不恢复优惠券。
- 邮件：给客户发“未凑齐球友，已全额原路退款”（中英双语）；给管理员发汇总。
- 前台：报名页和详情页加一句说明“开赛前 24 小时仍无其他球友报名，将自动全额原路退款”。

### 上线前
- 在生产库跑迁移 0023 再合并。
- 先用 Stripe 沙盒 + `preview` 分支测一次真实退款。

## PR-C：赛后评论模块（迁移 `0024_session_reviews`，基于 PR-B）

按 3.2 规格分阶段，本轮做 Phase 1 + Phase 2：

1. **文字评论**：`session_reviews` 和 `review_media` 两张表、`/review?t=` 提交页、提交/修改/删除 API、后台“评论审核”tab、场地详情页“球友留言”墙、跟进邮件里的“留下评价”按钮。
2. **图片**：`@vercel/blob` 客户端直传，浏览器端压缩并去掉 EXIF，每条最多 5 张。
3. **视频**（≤1 段，≤50MB / ≤60 秒）：代码已写，默认关闭（`REVIEW_VIDEO_ENABLED`），确认流量成本后再开。
4. 本轮不做：评价修改（可删除后重写）、场地卡片平均分。

### 开放问题的默认取舍（可改）
- O-1 每个预订只有联系人能写 1 条。
- O-2 视频上限先 50MB。
- O-3 待审核媒体用不可猜测的公开 URL，拒绝后 7 天删除。
- O-4 保留 1–5 星（可选填），本轮不在场地卡片显示平均分。
- O-5 本轮在提交页放隐私说明，不单独做隐私政策页。

### 需要你在 Vercel 里配置
- 创建 Blob Store（自动注入 `BLOB_READ_WRITE_TOKEN`）。
- 设置 `REVIEW_TOKEN_SECRET`（跟进邮件退订链接已经在用，确认生产已有）和 `REVIEWS_ENABLED=true`。

## 待决定：已报名场次的日期 / 时间 / 价格被锁定（“灰色部分的数据不能改”）

**状态**：已确认问题，方案待 review 后选择（2026-10-19 记录）。代码未改。

### 现状
- 场次只要有 `confirmed` 预订，后台编辑表单里的场地、日期、开始/结束时间、价格就变灰不可改（`components/views/admin-view.tsx` 的 `hasActiveBookings`），并显示提示“该场次已有有效报名，场地、日期、时间和价格已锁定”。
- 服务端同样拦截：`app/api/admin/sessions/[id]/route.ts` 中有 confirmed 预订且这些字段变化时返回 `409 locked_fields`。
- 名额、形式、寻找水平、发布状态仍可修改。
- 锁定原因：保护已付款球友。直接改时间或价格，已报名的人不知情，会去错时间，或与已付金额对不上。

### 推荐方案

**方案 A（推荐）：允许修改 + 自动通知**
- 放开锁定，保存前弹窗确认“将通知 N 位已报名球友”。
- 改日期/时间：自动给已报名球友发双语邮件，附新的日历文件（.ics），并说明不方便可回复邮件申请退款（管理员在后台退款）。
- 改价格：只影响之后的新报名；已付款的不补收、不退差价（预订里已记录当时价格 `session_price_pence`）。
- 改场地：同样发通知邮件，邮件里写新地址。
- 工作量：中等（服务端去掉锁 + 通知邮件 + 前端确认弹窗 + 测试）。

**方案 B：只放开价格**
- 价格可改（只影响新报名），场地/日期/时间仍锁定。
- 工作量：小。适合价格常调整、时间基本不变的情况。

**方案 C：保持锁定，提供替代办法**
- 规则不变。在锁定提示旁加“复制为新场次”按钮，一键生成同场地的新场次草稿；旧场次由管理员手动处理已报名的人（联系或退款）。
- 工作量：小。最安全，但操作步骤最多。

**可选增强（可与 A 组合）**：改日期/时间时，邮件里给一个“一键退款”链接（签名 token，复用评价链接的做法），球友自助退款，不用管理员处理。工作量再加中等。
