# 订场助手流程图与话术

以下为当前订场助手的询问、确认提交及注册流程。需求收集阶段的话术为示例，由模型根据上下文生成；已提供的信息会跳过，每次只追问一到两个缺失问题。

## 需求收集与提交

```mermaid
flowchart TD
    A["打开订场助手"] --> B["地点<br/>你想在哪个场地或区域打球？"]
    B --> C["日期和时间<br/>你想哪天打？从几点到几点？"]
    C --> D{"是否需要寻找球友？<br/>需要我们帮你找搭子吗？"}

    D -->|需要| E["网球水平<br/>你的网球水平是多少？"]
    E --> F["单双打<br/>你想找单打还是双打的搭子？"]
    D -->|不需要| G["联系方式<br/>方便留下姓名和邮箱吗？电话可选。"]
    F --> G

    G --> H["汇总需求<br/>地点、日期、时段、搭子需求和联系方式<br/>说明：这是待团队审核的请求。"]
    H --> I["立即显示「确认并提交订场需求」按钮<br/>点击按钮或键入「确认」即可提交；<br/>需要修改，请直接输入改动内容。"]

    I --> J{"用户操作"}
    J -->|点击按钮或键入确认| K{"检查登录状态"}
    J -->|输入其他内容| U["修改需求<br/>更新资料，必要时追问缺失信息"]
    U --> H

    K -->|已登录| S["提交需求"]
    K -->|未登录| L["鼓励注册<br/>要不要注册 Tennis Match 账号？<br/>我们可以复用已有资料，在这里补齐剩余内容。"]

    L -->|注册账号| R["进入助手内注册流程"]
    L -->|已有账号| M["邮箱＋密码框<br/>登录已有账号"]
    L -->|暂不注册| S
    R -->|注册成功| S
    M -->|登录成功| S

    S --> T["提交成功<br/>已收到你的订场需求！<br/>我们会尽快联系你确认。"]
```

汇总时直接显示按钮，无需先发送确认再点击一次提交。英文对话也可键入 `confirm`。其他输入用于修改需求；修改期间隐藏旧提交按钮，收到新的完整汇总后重新显示。

这里检查的是登录状态。已有账号但未登录的用户可以选择登录；注册是可选项，用户也可以直接以游客身份提交。

## 助手内注册

```mermaid
flowchart TD
    A["复用姓名、邮箱、电话<br/>以及已知的网球水平和单双打偏好"]
    A --> B["姓名或邮箱缺失时补问<br/>你想使用什么姓名／邮箱注册？"]
    B --> C["网球水平缺失时补问<br/>你的网球水平是多少？请选择等级。"]
    C --> D["常打时段<br/>你平时喜欢在什么时间打网球？<br/>周末／工作日晚上／上午／下午／任意时间"]
    D --> E["单双打偏好缺失时补问<br/>你平时更喜欢单打、双打，还是都可以？"]
    E --> F["密码框<br/>请在下方密码框设置密码，完成账号注册。<br/>至少 8 个字符，输入内容遮蔽显示"]
    F --> G["点击「注册账号并提交需求」"]
    G --> H{"注册结果"}
    H -->|成功| I["自动登录并提交订场需求"]
    H -->|邮箱已注册| J["提示邮箱已存在<br/>返回并选择「我已有账号」登录"]
    H -->|其他失败| K["显示错误，保留资料<br/>重新输入密码后重试"]
```

密码框的内容直接发送给账号接口，不进入模型对话、订场需求或浏览器存储。注册成功而订场提交失败时，保留登录状态和需求，用户可重试提交。
